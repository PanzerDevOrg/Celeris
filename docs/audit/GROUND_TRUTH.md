# Ground truth: Celeris as it is today

**Status:** WS-1 deliverable, written before any code change. Normative for the audit work: when this file and the
original audit disagree, this file wins until the maintainer says otherwise.

**Snapshot:** branch `master` at `82c4b49` (Celeris `0.3.1.1`), build logic `bichal/BichalBuildLogic` at `aab7d10`,
Tessera at `a767396`. Verified on 2026-10-27 on a 4-vCPU x86-64 Linux container (AVX2, AVX-512F, FMA), GCC 13.3,
Clang 18.1, CMake 3.28, OpenJDK 21.0.12 and Temurin 25.0.5.

Tessera has its own file: [`bichal/Tessera` `docs/audit/GROUND_TRUTH.md`](https://github.com/bichal/Tessera/blob/master/docs/audit/GROUND_TRUTH.md).

## 1. What Celeris is

A **library mod** for NeoForge and Fabric (mod id `celeris`, group `net.bichal.mods`, package
`net.bichal.mods.celeris`). It adds nothing visible in game; other mods (Tessera, Velox) depend on it. It is **not**
a physics engine in the general sense: its physics package is a batch integrator for simple item-like bodies that
reproduces vanilla `Entity.move` rules, plus a spatial-hash broadphase.

Licenses: code AGPL-3.0-only, assets and docs CC BY-NC-SA 4.0 (`LICENSE`, `LICENSE-AGPL`, `LICENSE-CC`, `NOTICE`).

|---|---|---|
| Off-heap memory | `core.memory.backend.MemoryBackend`, `CelerisRuntime`, `FfmMemoryBackend` (ffm), `UnsafeMemoryBackend`, `HeapMemoryBackend` | Selection order FFM → Unsafe → heap; `-Dceleris.compatMode=true` forces heap. FFM uses `Arena.ofShared()` |

| Graphs and pipelines | `core.topology.*`, `graph.segmented.*`, `graph.discrete.*`, `pipeline.continuous.*`, `pipeline.discrete.*`, `pipeline.transit.*`, `api.transit.*` | Pipe/wire networks, item transport, client item table |

There is no `celeris.api` module boundary: "API" is a package convention (`net.bichal.mods.celeris.api.*`) and
many public types live outside it.

## 4. Native code (real)

**`celeris_physics`** (`native/`): C++20, one shared library per platform with every ISA variant inside.
`cp_api.cpp` detects the ISA at load time (CPUID/XGETBV on x86-64) and dispatches to `cp_isa_generic.cpp`
(SSE2 / any AArch64), `cp_isa_avx2.cpp` (`-mavx2 -mfma`, `/arch:AVX2`), `cp_isa_avx512.cpp`
(`-mavx512f -mavx512dq -mavx512vl`, `/arch:AVX512`, opt-in) or `cp_isa_neon.cpp`. `cp_kernel.inc` and
`cp_broadphase.inc` are compiled once per ISA inside an anonymous namespace. Default visibility is hidden.

- **Exported symbols** (`nm -D --defined-only libceleris_physics.so | grep ' T '`): `cp_abi_version`,
  `cp_layout_signature`, `cp_active_isa`, `cp_force_isa`, `cp_step`, `cp_broadphase`, `cp_bucket_count`,
  `JNI_OnLoad` and six `Java_..._JniPhysicsKernel_*` entry points. Nothing else.
- **Determinism:** `-ffp-contract=off`, no `-ffast-math`, `/fp:precise`. Two modes exist in the C ABI:
  `CP_MODE_VANILLA` (bit-identical to `JavaPhysicsKernel` on every ISA, enforced by `PhysicsParityTest` and
  `cp_selftest`) and `CP_MODE_FUSED` (FMA by definition). There is **no** `CP_MODE_IEEE` name and **no**
  `CP_MODE_FIXED` or fixed-point code.
- **Java bindings:** JNI first (`JniPhysicsKernel`, no launch flag), FFM second (`NativePhysicsKernel`, downcalls
  linked as critical: `Linker.Option.isTrivial()` on Java 21, `critical(false)` on Java 25; library looked up in
  `Arena.global()`), then the Java kernel.
- **Tests:** `cp_selftest` (scenarios, ISA parity, broadphase vs brute force) and `cp_fuzz` (hostile inputs: NaN,
  ±inf, huge values, misaligned slab, malformed calls). Both are plain executables registered with CTest, **not**
  libFuzzer targets.

**`zstd`** (`native/zstd`): zstd 1.5.7 from the official tarball (SHA-256 checked) plus a JNI shim
(`celeris_zstd_jni.c`).

Prebuilt binaries are **not** committed in Celeris; CI builds them per platform. Locally, the Java build falls back
to the Java kernel and deflate when they are missing.

## 5. Build, test and CI (real)

| Need | Real command |
|---|---|
| Build + unit tests, active version | `./gradlew :1.21.1:build` (or `./gradlew build` for every node) |
| Release jars | `./gradlew buildAndCollect` |
| Throughput comparisons | `./gradlew benchmarkTest` (JUnit `@Tag("benchmark")`: `Nearest3BenchmarkTest`, `RingBufferBenchmarkTest`, `PhysicsBackendBenchmarkTest`) |
| Native kernel | `cmake -S native -B <dir> && cmake --build <dir> && ctest --test-dir <dir>`; from Gradle, `buildNativeCelerisPhysics` (registered by bichal-build-logic), or `-Pbichal.native.build=true` |
| Release | `../bichal-build-logic/bichal release celeris --push` |

**There is no `:celeris.native:cmakeBuild` task and no JMH source set.** The numbers in `docs/benchmarks.md` say
"JMH 1.37", but no JMH harness is in this repository; they were measured outside it (with Velox for the in-game
table). `benchmarkTest` prints throughput and asserts nothing; it writes no JSON.

**Prerequisites that are not obvious:**

1. bichal-build-logic must be checked out next to the mod as `../bichal-build-logic` (the build fails at settings
   time otherwise, with a message saying so).
2. **Gradle must run on JDK 25.** Fabric Loom 1.18.3 (pulled in by the build logic) refuses a Java 21 Gradle JVM:
   `Dependency requires at least JVM runtime version 25. This build uses a Java 21 JVM.` The Java 21 toolchain
   is still needed to compile the 1.21.x nodes. The README's developer section only says "JDK 21" (Tessera says the
   same); both are wrong for a fresh checkout.

**CI:**

- `ci.yml` delegates everything to `bichal/BichalBuildLogic/.github/workflows/mod-ci.yml` pinned to commit
  `4f611b9`: build, test, package, verify and a release dry run on every push and PR; publish to GitHub Releases,
  Modrinth, CurseForge and the gh-pages Maven repository on `v*` tags.
- `native-sanitizers.yml`: ASan + UBSan (+ float-cast-overflow) on `ubuntu-latest` and `ubuntu-24.04-arm`, running
  `cp_selftest` and `cp_fuzz`. No TSan.
- `descriptions.yml`: README → Modrinth/CurseForge descriptions.
- Not present: CodeQL, docs publishing, fuzzing with coverage guidance, benchmark regression gate, Zig
  cross-compilation, cosign signing.

## 7. Defects found while verifying (not fixed in WS-1)

| # | Severity | Finding | Evidence | Effect |
|---|---|---|---|---|
| D1 | **P0** (fixed in source) | JNI symbol names used the old `com.bichal` package; the Java classes are `net.bichal` since `0f62ed3` | `native/src/cp_jni.cpp:18` `Java_com_bichal_mods_celeris_physics_JniPhysicsKernel_##name`; `native/zstd/celeris_zstd_jni.h:24` `Java_com_bichal_mods_celeris_core_memory_ZstdJniBinding_##name`; classes are `net.bichal.mods.celeris...` | In 0.3.1.1 the JNI physics kernel and JNI zstd cannot link (`UnsatisfiedLinkError`). Physics falls back to FFM (only with `--enable-preview` on Java 21) or the Java kernel; zstd falls back to FFM or deflate. Every user without flags on 1.21.x loses the native paths the README advertises |
| D2 | P2 | Build docs say JDK 21; Gradle needs JDK 25 | §5 | A new contributor's first build fails |
| D3 | P3 | `docs/benchmarks.md` cites JMH that the repository does not contain | §5 | Numbers are not reproducible from this repository |

**D1 reproduced** against the library built from this commit, with a one-method class in each package
(`static native int nativeAbiVersion()`, then `System.load(libceleris_physics.so)`), before the fix:

```
net.bichal: UnsatisfiedLinkError 'int net.bichal.mods.celeris.physics.JniPhysicsKernel.nativeAbiVersion()'
com.bichal: abi=4
```

The failure is silent by design: `CelerisPhysics` and `CelerisCodecs` catch `Throwable` from the probe, log the
reason once and pick the next backend, so nothing crashes and nothing in the README's numbers holds for those users.
Tessera has the same defect (see its ground truth).

D1 is fixed in source by renaming the prefix to `Java_net_bichal_` in `native/src/cp_jni.cpp` and `native/zstd/celeris_zstd_jni.h`.
The rebuilt `libceleris_physics.so` exports the new names and `ctest` passes. Released jars still need a rebuild and release, which is outside WS-1's "no code change" rule. This should land before WS-4/WS-5.

## 9. How this was verified

```bash
# layout and API
git ls-files | sed 's|/[^/]*$||' | sort | uniq -c
grep -rn "Arena\.\(ofAuto\|ofConfined\|ofShared\|global\)" src
grep -rn "Linker.Option" src

# native kernel: build, self-test, fuzz, exported symbols
cmake -S native -B build-native -DCMAKE_BUILD_TYPE=Release
cmake --build build-native -j
ctest --test-dir build-native --output-on-failure      # cp_selftest, cp_fuzz: 2/2 passed
nm -D --defined-only build-native/libceleris_physics.so | grep ' T '

# Java build (bichal-build-logic checked out as ../bichal-build-logic, Gradle on JDK 25)
JAVA_HOME=<jdk-25> ./gradlew :1.21.1:build
```
